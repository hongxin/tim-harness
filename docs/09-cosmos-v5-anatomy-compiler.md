# Cosmos v5 重生方案 —— Anatomy 编译器

## 用户的核心洞察

> "把 Anatomy 的逻辑学会，恰好对于人机交互智能体生成内容，
> 比较机械化、规则化的结果，总共的变化其实不多，
> 所以可行性应该极高才对。"

这句话点破了本质：**Anatomy 的输出看似千变万化，但其内在逻辑是有限的、可枚举的、规则化的**。我们不需要每次调用 LLM 生成，而可以把这套逻辑"编译"为确定性的本地渲染引擎。

## 分析：Anatomy 到底在做什么？

Anatomy 的每次输出都在回答同一个问题：
**"这个抽象的技术过程，如果是一台物理机器，会长什么样？"**

它包含四个固定环节：
1. **零件选择**：把每个概念映射为机械零件（漏斗→输入、齿轮→处理、管道→传输、仪表→监控）
2. **空间编排**：零件按流程排列，形成一条可读的"装配线"
3. **状态赋予**：每个零件有运行状态（转动/静止/卡住/发光）
4. **动态叙事**：数据在零件间流动，形成可观察的"机器运转"

这四个环节——**零件映射、空间编排、状态赋予、动态叙事**——全部可以用规则引擎实现，零 LLM 调用。

## 架构设计：Anatomy 编译器

```
┌─────────────────────────────────────────────────┐
│              会话消息流（已有数据）                 │
│  user → assistant(tool_calls) → tool → assistant │
└──────────────────┬──────────────────────────────┘
                   │ 提取
                   ▼
┌─────────────────────────────────────────────────┐
│         第一层：语义解析器（纯函数）                │
│                                                  │
│  输入：messages[]                                 │
│  输出：MachineBlueprint                           │
│    .stations: Station[]     // 工位序列           │
│    .conveyors: Conveyor[]   // 传送带             │
│    .gauges: Gauge[]         // 仪表               │
│    .narrative: Frame[]      // 帧序列             │
└──────────────────┬──────────────────────────────┘
                   │ 编译
                   ▼
┌─────────────────────────────────────────────────┐
│       第二层：零件工厂（规则引擎）                  │
│                                                  │
│  Station 查表：                                   │
│    read_file  → 检查站（放大镜 + 检验台）          │
│    write_file → 冲压站（模板 + 冲头）              │
│    run_js     → 反应釜（容器 + 搅拌器 + 电弧）     │
│    grep       → 筛选机（振动筛 + 收集槽）          │
│    spawn_agent→ 分装厂（母机器 + 子流水线）        │
│    skill      → 装配手册（书架 + 翻页器）          │
│    ...每个工具 = 一个精心设计的工位                 │
│                                                  │
│  Gauge 规则：                                     │
│    token 消耗 → 燃料表                            │
│    上下文占用 → 液位计                            │
│    缓存命中率 → 效率指示灯                         │
│    连续失败   → 警报灯                             │
└──────────────────┬──────────────────────────────┘
                   │ 渲染
                   ▼
┌─────────────────────────────────────────────────┐
│      第三层：Canvas 渲染引擎（60fps）              │
│                                                  │
│  布局：装配线（水平主轴 + 垂直工位）               │
│  动画：齿轮旋转 / 传送带滚动 / 液面波动 / 电弧闪烁  │
│  交互：hover 聚焦 / 点击展开 / 拖拽重排            │
│  配色：多巴胺色板（鲜艳、快乐、有观察动力）          │
└─────────────────────────────────────────────────┘
```

## 关键设计决策

### 1. 布局：装配线（非自由散布）

```
  用户输入          智能体推理            工具执行           输出装配
  ┌──────┐        ┌────────┐         ┌────────┐        ┌──────┐
  │ 📥   │───────▶│  ⚙️    │────────▶│  🔧   │───────▶│ 📤  │
  │ 漏斗 │ 传送带  │ 主齿轮 │  分配臂  │ 工位群 │ 传送带 │ 装配 │
  └──────┘        └────────┘         └────────┘        └──────┘
       │               │                   │                │
       ▼               ▼                   ▼                ▼
   输入仪表      思考进度环          执行状态灯        输出计数器
```

每个回合 = 一条装配线段，多回合首尾相连 = 完整工厂。

### 2. 配色：多巴胺色板

```
背景    #0D1117 → #161B22（深空蓝，让鲜艳色弹出）
主齿轮  #FFD700（金色，快乐与价值的象征）
输入    #FF6B9D（粉红，温暖的人类意图）
执行    #00E5FF（青色，机器的精确）
成功    #00FF88（荧光绿，多巴胺直接刺激）
失败    #FF4444（鲜红，紧急但醒目）
工具    按类别：
  读    #7CFC00（草绿）
  写    #FF8C00（橙）
  执行  #FFD700（金）
  搜索  #00CED1（青蓝）
  派生  #DA70D6（兰紫）
仪表    #FFA500（琥珀）
传送带  #4A9EFF（亮蓝）
```

### 3. 动画：六种核心机械运动

| 动画 | 参数 | 触发 |
|---|---|---|
| 齿轮旋转 | 250ms/转，8 齿 | 智能体正在思考 |
| 传送带滚动 | 纹路移动 30px/s | 数据在流转 |
| 活塞往复 | 1.5s 周期，6px 幅度 | 工具执行中 |
| 液面波动 | 正弦波，±2px | 上下文占用 |
| 电弧闪烁 | 随机触发，200ms | run_js 执行 |
| 指针摆动 | 弹性趋近目标值 | token 计数变化 |

### 4. 与现有 Cosmos 的关系

不替换，而是**新增一个视图模式**：
- 🌌 Cosmos（力导向）：保留，适合空间探索
- 🏭 Machine（装配线）：新增，适合过程理解

用户可以在两种模式间切换，各取所长。

## 实施计划

### 阶段 1：MachineBlueprint 解析器（纯函数，可测试）
- 从 messages[] 提取工位序列
- 计算传送带连接
- 生成仪表数据

### 阶段 2：零件工厂（Canvas 绘制函数库）
- 15+ 种工位绘制器（每种工具一个）
- 4 种仪表绘制器
- 传送带绘制器

### 阶段 3：装配线布局引擎
- 水平主轴布局
- 工位自动排列（避免重叠）
- 多回合串联

### 阶段 4：动画与交互
- 六种机械运动
- hover 聚焦 + 点击展开
- 相机跟随"当前活动工位"

### 阶段 5：集成与打磨
- 视图切换（🌌 ↔ 🏭）
- 多巴胺配色
- 性能优化
